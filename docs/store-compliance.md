# Store compliance

What the App Store and Google Play check, what the template already satisfies, and what each
project must fill in. Use it before the first submission and before any release that adds data
collection, a permission, an SDK or account features. The stores' own rules change; their consoles
are the final word (App Store Review Guidelines, Google Play Developer Policy Center).

Every item is classified ([production-readiness.md](production-readiness.md#classification)):
**CORE** (done by the template), **OPTIONAL**, **REQUIRES CONFIGURATION** (the project provides the
value or completes the form) or **PROJECT-SPECIFIC** (only when the product has the feature).

## What the template ships

Verified on the generated native projects (`expo prebuild`, Expo SDK 57):

| Item                   | Android                                                                                                                                                                                  | iOS                                                                                                                                                                                                   |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Permissions            | `INTERNET`, `ACCESS_NETWORK_STATE`, `ACCESS_WIFI_STATE`, `POST_NOTIFICATIONS`, `RECEIVE_BOOT_COMPLETED`, `VIBRATE`: all normal-level; `SYSTEM_ALERT_WINDOW` and external storage blocked | usage texts: none for the app's features (Face ID text removed: nothing uses biometrics); `NSLocalNetworkUsageDescription` comes from the development client, never prompted in release builds        |
| SDK levels             | target and compile SDK 36, minimum 24                                                                                                                                                    | the deployment target of Expo SDK 57                                                                                                                                                                  |
| Privacy manifests      | —                                                                                                                                                                                        | React Native and the Expo modules that use Required Reason APIs ship their own `PrivacyInfo.xcprivacy` (`expo-notifications`, `expo-application`, `expo-device`, `expo-constants`); the app adds none |
| Encryption             | —                                                                                                                                                                                        | `ITSAppUsesNonExemptEncryption: false` (HTTPS only)                                                                                                                                                   |
| Backups                | `allowBackup: false`                                                                                                                                                                     | secure storage items are this-device-only                                                                                                                                                             |
| Tracking               | none                                                                                                                                                                                     | none (no App Tracking Transparency needed)                                                                                                                                                            |
| Data collected by SDKs | Sentry (crash and diagnostics data) when a DSN is set; the Expo push service token when push is registered                                                                               | the same                                                                                                                                                                                              |

## Apple App Store

| Item                                                            | Class                         | What to do                                                                                                                                                                                                                                                                                                                                                                                                                          |
| --------------------------------------------------------------- | ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **App Privacy** (privacy "nutrition labels", App Store Connect) | REQUIRES CONFIGURATION        | declare every data type the app and its SDKs collect, from the [data inventory](../SECURITY.md#data-inventory): with Sentry, _Diagnostics → Crash Data_ (and _Performance Data_ with tracing), linked to the user when a user id is set; with analytics, _Usage Data_; with accounts, _Contact Info_ and _Identifiers_. For each: purpose, linked to the user or not, used for tracking or not                                      |
| **Privacy manifest** (`PrivacyInfo.xcprivacy`)                  | CORE / REQUIRES CONFIGURATION | covered for React Native and the Expo modules (above). A project whose own native code, or a dependency without its own manifest, uses a Required Reason API (user defaults, file timestamps, system boot time, disk space, active keyboards) declares it in `apps/mobile/app.config.ts` → `ios.privacyManifests`. After each upload, App Store Connect emails any missing reason (ITMS-91053): fix it before submitting for review |
| **Permission usage texts** (`NS…UsageDescription`)              | CORE / PROJECT-SPECIFIC       | only for permissions the app asks: set each through the module's config plugin option (or `ios.infoPlist`), saying specifically what for, in the app's language. Unused texts are removed (like the Face ID one)                                                                                                                                                                                                                    |
| **App Tracking Transparency**                                   | PROJECT-SPECIFIC              | only if the app tracks: links its data with other companies' data for advertising or measurement, or shares it with data brokers. Then `expo-tracking-transparency`, `NSUserTrackingUsageDescription`, the prompt before any tracking, and "Data used to track you" in App Privacy                                                                                                                                                  |
| **Account deletion**                                            | CORE                          | users who create an account in the app must be able to start deleting it there (Guideline 5.1.1(v)): Settings → Delete account, with the password and a destructive confirmation; the API deletes the account and everything it owns at once (`apps/mobile/src/features/account/DeleteAccountScreen.tsx`)                                                                                                                           |
| **Sign in with Apple**                                          | PROJECT-SPECIFIC              | if the app offers third-party or social sign-in, review Guideline 4.8 (an equivalent privacy-focused option)                                                                                                                                                                                                                                                                                                                        |
| **Age rating**                                                  | REQUIRES CONFIGURATION        | the questionnaire in App Store Connect                                                                                                                                                                                                                                                                                                                                                                                              |
| **Export compliance**                                           | CORE                          | declared in `Info.plist` (HTTPS only). Review it if the app adds its own cryptography                                                                                                                                                                                                                                                                                                                                               |
| **Metadata and screenshots**                                    | REQUIRES CONFIGURATION        | name, subtitle, description, keywords, category, support URL, privacy policy URL; iPhone screenshots at the sizes App Store Connect asks for (iPad screenshots only if `supportsTablet` is turned on)                                                                                                                                                                                                                               |
| **Review notes**                                                | REQUIRES CONFIGURATION        | a working demo account (the app requires sign-in), how to reach every feature, anything only enabled by a flag or a region                                                                                                                                                                                                                                                                                                          |
| **In-app purchases**                                            | PROJECT-SPECIFIC              | digital goods and subscriptions must use Apple's in-app purchase (Guideline 3.1.1)                                                                                                                                                                                                                                                                                                                                                  |
| **OTA updates**                                                 | CORE                          | updates change JavaScript only and never the app's purpose (Guideline 2.5.2 / 3.3.1(b)); features that change what reviewers approved go through a store release ([releases.md](releases.md#ota-updates))                                                                                                                                                                                                                           |

## Google Play

| Item                                         | Class                         | What to do                                                                                                                                                                                                                                                                                 |
| -------------------------------------------- | ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Data safety** form                         | REQUIRES CONFIGURATION        | from the [data inventory](../SECURITY.md#data-inventory): data collected and shared (with Sentry: _App info and performance → Crash logs, Diagnostics_; with push: _Device or other IDs_; with analytics: _App activity_), encrypted in transit (yes), deletion request mechanism          |
| **Permissions declaration**                  | CORE                          | not needed: every merged permission is normal-level (above). A project adding a restricted permission (SMS, call log, background location, all files access, exact alarms…) completes its declaration                                                                                      |
| **Account deletion**                         | CORE / REQUIRES CONFIGURATION | deletion from inside the app (CORE: Settings → Delete account) **and** a web page where users can request it, linked in the Data safety form: the landing's `https://<domain>/delete-account/` (CORE), with the request address of `apps/landing/src/lib/site.ts` (REQUIRES CONFIGURATION) |
| **Target SDK**                               | CORE                          | SDK 36 with Expo SDK 57. Google raises the required target level for new apps and updates every year (deadline: end of August): check Play Console's requirement and stay on a current Expo SDK ([releases.md](releases.md#expo-sdk-upgrades))                                             |
| **Content rating**                           | REQUIRES CONFIGURATION        | the IARC questionnaire in Play Console                                                                                                                                                                                                                                                     |
| **App access**                               | REQUIRES CONFIGURATION        | reviewer credentials for the sign-in, and instructions                                                                                                                                                                                                                                     |
| **Ads, target audience, other declarations** | REQUIRES CONFIGURATION        | the Play Console "App content" tasks; the Families policy if children are an audience                                                                                                                                                                                                      |
| **Store listing**                            | REQUIRES CONFIGURATION        | short and full description, 512×512 icon, 1024×500 feature graphic, at least two phone screenshots                                                                                                                                                                                         |
| **Testing before production**                | REQUIRES CONFIGURATION        | new personal developer accounts must run a closed test (at least 12 testers for 14 days, at the time of writing) before production access                                                                                                                                                  |
| **Billing**                                  | PROJECT-SPECIFIC              | digital goods use Google Play Billing                                                                                                                                                                                                                                                      |

## Privacy

| Item                                      | Class                         | What to do                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ----------------------------------------- | ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Privacy policy**                        | CORE / REQUIRES CONFIGURATION | both stores require a public URL: the landing's `https://<domain>/privacy/` (and `/es/privacy/`), whose sections follow the [data inventory](../SECURITY.md#data-inventory) (CORE); its legal text, the SDKs and providers that receive data and the retention periods are the project's to write (REQUIRES CONFIGURATION), and its template notice says so until then                                                                                                                                           |
| **Terms of service**                      | PROJECT-SPECIFIC              | when the product needs them (accounts, payments, user content)                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| **Data collection inventory**             | CORE                          | [SECURITY.md](../SECURITY.md#data-inventory), kept current by every feature that adds data (DEFINITION_OF_DONE.md)                                                                                                                                                                                                                                                                                                                                                                                               |
| **Retention**                             | REQUIRES CONFIGURATION        | on the device, defined in the inventory; on the API, [what it keeps](../SECURITY.md#data-the-api-keeps) and for how long; on providers (Sentry, analytics) and in database backups, set and written in the privacy policy                                                                                                                                                                                                                                                                                        |
| **Deletion**                              | CORE / REQUIRES CONFIGURATION | on the device, sign-out clears the session, caches and images, and uninstalling removes the rest (the iOS Keychain session is wiped at the next installation); on the server, the API deletes an account and everything it owns at its owner's request (`POST /api/account/deletion`, [adr/0012-account-deletion.md](adr/0012-account-deletion.md)), from the app's deletion screen (Settings → Delete account); the web page Google Play asks for comes with the landing (its request address is the project's) |
| **Analytics consent**                     | CORE                          | nothing is sent before the user agrees (Settings); withdrawing consent stops it; no provider ships                                                                                                                                                                                                                                                                                                                                                                                                               |
| **Crash reporting data**                  | CORE                          | scrubbed of credentials, emails and query strings; no screenshots or view hierarchies; an opaque user id only ([SECURITY.md](../SECURITY.md#logging-and-reports))                                                                                                                                                                                                                                                                                                                                                |
| **Push tokens**                           | REQUIRES CONFIGURATION        | handled by the backend: stored per device, removed at sign-out and when invalid ([mobile-architecture.md](mobile-architecture.md#notifications))                                                                                                                                                                                                                                                                                                                                                                 |
| **Regional law** (GDPR, CCPA/CPRA, LGPD…) | PROJECT-SPECIFIC              | consent, access and deletion rights, data processing agreements with the SDK providers, as the markets require                                                                                                                                                                                                                                                                                                                                                                                                   |

## Before each submission

- [ ] The data inventory, App Privacy and Data safety still match what the build collects (new
      SDKs, events, permissions, account features).
- [ ] Every permission the build asks has a specific usage text; nothing unused is declared.
- [ ] No ITMS-91053 (privacy manifest) email for the uploaded build.
- [ ] The privacy policy and support URLs work.
- [ ] The reviewer account works against the production API.
- [ ] Screenshots and descriptions show the current version.
- [ ] Account deletion works, if accounts can be created in the app.
