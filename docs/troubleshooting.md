# Troubleshooting

The messages below are the ones the tools actually print. Search this page for a few words of
the error. This page covers the server side: the web image, the deployment, the server and its
checks. The messages of local development, the app's builds and its end-to-end flows are in the
README's table ([README.md](../README.md#troubleshooting)), the manual
([manual.md](manual.md#15-when-something-fails)) and [testing.md](testing.md#end-to-end); what to do
when production misbehaves, in [incident-response.md](incident-response.md).

## Web image

| Message                                                                                                                                          | Cause                                                                                                                       | Fix                                                                                                                                                              |
| ------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The web container exits: `Environment variable APP_ORIGIN is invalid: the public origin of the site, ...`                                        | The image has no `APP_ORIGIN` (it has no default), or one with a path or a trailing slash                                   | Set it to the origin only (`https://app.example.com`); on the server it comes from `APP_DOMAIN` in `server.env` ([environment.md](environment.md#web-variables)) |
| The web container exits: `Environment variable APPLE_TEAM_ID is invalid: ... set together with IOS_BUNDLE_ID` (or another of the app's identity) | Half of a pair, or a value of the wrong shape (a fingerprint in lowercase, without colons)                                  | Set both values of the pair, or neither; the fingerprints in capitals, `AB:CD:…`, comma-separated ([deploy-vps.md](deploy-vps.md#6-the-files-on-the-server))     |
| The web container exits: `Environment variable APP_RELEASE is invalid`                                                                           | `APP_RELEASE` set by hand in `web.env`, with characters the image will not embed in `/release.json`                         | Remove it from `web.env`: the image carries its build's release                                                                                                  |
| The web container exits: `Environment variable NGINX_LOCAL_RESOLVERS is invalid`                                                                 | No nameserver in the container's `/etc/resolv.conf`                                                                         | Run it on a Docker network (Compose's default); nginx looks `API_UPSTREAM` up again every 10 seconds through that nameserver                                     |
| `/api/...` answers `502 {"message":"The API could not be reached"}` while `/healthz` answers 200                                                 | The API is down, or `API_UPSTREAM` names a host nginx cannot resolve (a name only in `/etc/hosts`, `docker run --add-host`) | Start the API; give it a DNS name (a Compose service) ([incident-response.md](incident-response.md#1-api-down))                                                  |
| `/.well-known/apple-app-site-association` or `/.well-known/assetlinks.json` answers 404                                                          | The app's identity is not set on the image (expected until it is)                                                           | Set the pair in `web.env` and recreate `web` ([incident-response.md](incident-response.md#18-app-links-open-the-browser))                                        |

## Smoke test

| Message                                                                                           | Cause                                                                                                                            | Fix                                                                                                                               |
| ------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `FAIL  release: release <a>, expected <b>`                                                        | The web image of another build still serves (rollout not finished, the wrong digest, or `APP_RELEASE` set by hand in `web.env`)  | Wait for the rollout, check the deployed digest and `web.env`; roll back if it does not converge ([ci-cd.md](ci-cd.md#rollback))  |
| `FAIL  API through the web server: status 502, expected 404`                                      | The web server cannot reach the API                                                                                              | [incident-response.md](incident-response.md#1-api-down)                                                                           |
| `FAIL  probes not public: status 200, expected 404`                                               | The web server's configuration exposes `/api/health/`                                                                            | Restore the `location` block of `apps/landing/nginx/default.conf.template`; probes stay private                                   |
| `FAIL  landing: links on the build placeholder`                                                   | nginx served the landing without writing `APP_ORIGIN` into it: its `sub_filter` lines were changed or removed                    | Restore `location /` of `apps/landing/nginx/default.conf.template`                                                                |
| `FAIL  share picture: status 404` (or `landing: share picture on another origin`)                 | The image has no `og.png` (the landing's `public/` did not reach it), or its `og:image` was not written with `APP_ORIGIN`        | Restore the landing's copy in `apps/landing/Dockerfile` and `location /` of `apps/landing/nginx/default.conf.template`            |
| `FAIL  the app's links without the app: status 30x, expected 200`                                 | Something redirects `/app/*` (an edge rule, a changed `location`): an emailed link's token rides in the fragment of that address | Remove the redirect; `/app/*` answers the open-in-app page at its own address ([ADR 0008](adr/0008-public-site-and-app-links.md)) |
| `FAIL  Apple's link file: status 404: the app's identity is not set` (with `--require-app-links`) | `APPLE_TEAM_ID` and `IOS_BUNDLE_ID` are not set on the web image                                                                 | Set them in `web.env` ([environment.md](environment.md#web-variables))                                                            |
| `FAIL  API readiness: status 503, expected 200`                                                   | A hard dependency is down (the message says which)                                                                               | [incident-response.md](incident-response.md#2-readiness-failing)                                                                  |

## Deployment and operations

| Message                                                                                                                             | Cause                                                                                                                                           | Fix                                                                                                                                                                                  |
| ----------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Deploy: `Wrong branch: Run Deploy from main; it deploys any commit on main.`                                                        | The workflow was run from another branch                                                                                                        | Run it from `main`, with the branch, tag or commit to deploy as `ref`                                                                                                                |
| Deploy: `Not on main: <ref> (<sha>) is not on main.`                                                                                | Only reviewed, merged code ships                                                                                                                | Merge the change first; a rollback deploys an earlier commit of `main`                                                                                                               |
| Deploy: `IMAGE_PREFIX: Set the repository variable IMAGE_PREFIX to ghcr.io/<owner>/<repository>, lowercase`                         | The repository variable is missing or not lowercase                                                                                             | [deploy-vps.md](deploy-vps.md#7-github-settings)                                                                                                                                     |
| Deploy: `DEPLOY_HOST: Set DEPLOY_HOST in the staging environment` (or `PUBLIC_URL`, `DEPLOY_SSH_KEY`, `DEPLOY_KNOWN_HOSTS`)         | The environment lacks a setting                                                                                                                 | [deploy-vps.md](deploy-vps.md#7-github-settings)                                                                                                                                     |
| Deploy: `Server unreachable: Could not connect to <host> over SSH.`                                                                 | The server is down, the firewall closes 22 to the runners (`admin_cidrs`), or the key or the host key changed                                   | Check the server and `ssh -i <key> deploy@<host>`; a new server needs a new `DEPLOY_KNOWN_HOSTS`                                                                                     |
| Deploy: `Server files out of date: /srv/app differs from deploy/vps in this release`                                                | A release changed `compose.yaml`, the `Caddyfile`, a script or `realip.conf`                                                                    | Copy them from the release ([deploy-vps.md](deploy-vps.md#update-the-server-files)), then deploy again                                                                               |
| Deploy: `Image: Not an image of <prefix> pinned by digest ... A record made under another IMAGE_PREFIX cannot be reused`            | `IMAGE_PREFIX` changed since staging recorded this commit's images                                                                              | Deploy a newer commit, which builds and records its images under the new prefix                                                                                                      |
| Deploy: `Rolled back: The smoke test failed: the previous release is running again.`                                                | The release went live but failed the smoke test; `rollback.sh` put the previous one back                                                        | The smoke test's `FAIL` lines say why ([above](#smoke-test)); fix forward through a pull request                                                                                     |
| `deploy: another deployment or rollback is running on this server; run this again once it has finished`                             | A second `deploy.sh` or `rollback.sh` while one runs (the workflow and a person)                                                                | Wait for the first one; nothing was changed                                                                                                                                          |
| `deploy: <file> is missing next to compose.yaml (copy <file>.example and fill it in)`                                               | A settings file was not created on the server (`db.env` and `backup.env` too with `COMPOSE_PROFILES=db`)                                        | [deploy-vps.md](deploy-vps.md#6-the-files-on-the-server)                                                                                                                             |
| `deploy: the migration failed; the running release keeps serving`                                                                   | `api-migrate` failed                                                                                                                            | [incident-response.md](incident-response.md#10-failed-database-migration)                                                                                                            |
| `Error: P3009 migrate found failed migrations` from `api-migrate`                                                                   | An earlier migration failed and was not resolved                                                                                                | [database.md](database.md#when-a-migration-fails)                                                                                                                                    |
| `deploy: the data services did not start`, and `db-init: ... in db.env must be 24 or more letters and digits` in the database's log | `db-init.sh` refused a password of `db.env` at the database's first start; the volume keeps a database without `app`, which never turns healthy | Correct `db.env` (`openssl rand -hex 24`), remove the container and its volume, which holds no data yet (`docker rm -f app-db-1 && docker volume rm app_db_data`), then deploy again |
| The server's Redis exits: `REDIS_PASSWORD in redis.env must be 24 or more letters and digits (openssl rand -hex 24)`                | `redis.env` without a password, or one with other characters                                                                                    | `openssl rand -hex 24` into `redis.env` and the `REDIS_URL` of `api.env`                                                                                                             |
| `NOPERM` in a Redis error on the server                                                                                             | A key outside `app:*` (another `REDIS_KEY_PREFIX`) or a command the server's ACL does not list                                                  | The same prefix in the ACL line of `deploy/vps/compose.yaml` ([deploy-vps.md](deploy-vps.md#6-the-files-on-the-server))                                                              |
| `password authentication failed for user "app_runtime"` in the API's log; readiness 503 `Database unreachable`                      | The password changed in one place only: the database on the server and `api.env` disagree                                                       | PostgreSQL first, then the files ([deploy-vps.md](deploy-vps.md#change-a-setting-or-a-secret))                                                                                       |
| `self-signed certificate in certificate chain` in the API's log, with a managed database                                            | node-postgres reads `sslmode=require` as `verify-full`, and the provider signs with its own CA                                                  | End both URLs with `?sslmode=require&uselibpqcompat=true` ([deploy-vps.md](deploy-vps.md#6-the-files-on-the-server))                                                                 |
| `backup` is `unhealthy` in `docker compose ps`                                                                                      | No backup in the last 26 hours: `pg_dump` fails (a wrong `PGPASSWORD`, a full disk)                                                             | Its log says why (`docker compose ... logs backup`); then one at once, `exec backup sh /usr/local/bin/backup.sh now` ([deploy-vps.md](deploy-vps.md#backups))                        |
| `rollback: no previous release recorded (release.previous.env)`                                                                     | Only one release has gone live on this server                                                                                                   | Nothing to go back to; deploy an earlier commit instead ([deploy-vps.md](deploy-vps.md#roll-back))                                                                                   |
| `Could not send ...: connection` or a timeout from `mail test` on DigitalOcean                                                      | DigitalOcean blocks outbound SMTP (25, 465, 587) on many accounts                                                                               | The provider's port for that case (2525 with STARTTLS), or ask DigitalOcean to lift the block ([deploy-vps.md](deploy-vps.md#6-the-files-on-the-server))                             |

## Infrastructure and observability as code

| Message                                                                                                                              | Cause                                                                                           | Fix                                                                                                                                           |
| ------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `FAIL  Terraform: fmt, init, validate, test, user data` from `pnpm iac:check`, with a file name                                      | A file Terraform would reformat, an invalid configuration or a failing `terraform test`         | `terraform fmt -recursive infra/terraform`, then the error the step printed above the summary ([ci-cd.md](ci-cd.md#infrastructure-as-code))   |
| `the given plugin ... does not match any of the checksums recorded in the dependency lock file`                                      | A provider changed without its checksums (the gate's `init` reads the lock file read-only)      | Update the provider with its checksums together (Dependabot does; by hand, `terraform providers lock` for the platforms the lock file lists)  |
| `FAIL  TFLint` or `FAIL  Trivy: misconfigurations, HIGH and CRITICAL`                                                                | A finding in `infra/terraform`                                                                  | Fix it; a deliberate exception is an inline `trivy:ignore` with its reason, reviewed                                                          |
| `alert <name>: runbook_url "..." must be docs/incident-response.md#<section>, a heading that exists` from `pnpm observability:check` | A runbook heading was renamed or the alert points at a section that does not exist              | Point the alert at the heading's anchor, or restore the heading                                                                               |
| `... reads "<metric>", which the API does not export (observability/api-metrics.json) and no recording rule writes`                  | A dashboard or rule reads a renamed, removed or misspelt metric                                 | Use the catalog's name; a new metric goes into the code, the catalog and its spec first ([observability.md](observability.md#metric-catalog)) |
| `alert <name>: no unit test in observability/prometheus/tests expects it to fire`                                                    | A new alert without its test                                                                    | Add a test with synthetic series that makes it fire, and one that it must not fire on                                                         |
| `FAILED:` with `alertname: ...` from promtool                                                                                        | A rule no longer fires as its test expects (a threshold, a label, an annotation text)           | Change the rule and its test together, on purpose ([alerting.md](alerting.md))                                                                |
| DAST: `A FAIL rule of .zap/rules.tsv was triggered, or a scan could not run`                                                         | ZAP found what a FAIL rule forbids (a missing header, an injection), or the stack did not start | The `zap-reports-*` artifact names the rule and the URL; fix the cause ([security.md](security.md#dynamic-analysis))                          |
